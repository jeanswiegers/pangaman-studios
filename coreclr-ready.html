CoreCLR Ready

Find the code that breaks with Domain Reload off and on CoreCLR, and see the fix before anything changes.

Unity is moving from Mono to the CoreCLR runtime, and turning off Domain Reload in Enter Play Mode Options makes entering Play mode faster (from Unity 6.8 it is the only option). Both changes break code that used to work: static fields keep their values between Play sessions, AppDomain APIs stop behaving the same, BinaryFormatter goes away. CoreCLR Ready scans your project's C# for these patterns, explains each one, links to Unity's documentation and, where a safe mechanical change exists, shows the exact edit as a diff.

What it checks

Mutable static state that survives Play mode with Domain Reload off (fields, events, auto-properties, singletons), AppDomain.GetAssemblies and DomainUnload, BinaryFormatter, Assembly.Location, pointer-to-int conversions, string.GetHashCode used as a stable value, non-default encodings, Assembly.LoadFile/LoadFrom, ManagedDebugger and [DllImport] into Mono runtime libraries. The rules table in the manual lists which ones have an automatic fix.

The analysis is static: it can't know whether a static value is meant to persist. Those cases are reported, not fixed, and you can silence one with a comment.
